# 设备与游戏兼容性

## 设备配置

适用配置为 R36S、ArkOS4Clone 08262026、Linux ARM64 4.4.189、RTL8188EU 无线芯片和 640×480 屏幕。支持的无线 USB ID 为 `0bda:8179` 和 `0bda:0179`，内核文件 SHA-256 为 `73a123c06c67c002605bef637ef458aa43448a501c48ce27756f16e846d57f7a`。

运行时使用掌机已有的 RetroArch、核心、EmulationStation、gptokeyb、systemd、NetworkManager 和基础网络工具。执行 `doctor` 可查看掌机配置与依赖检测结果。

## 平台范围

| 平台 | 联机时的核心选择 | 已验证范围与限制 |
| --- | --- | --- |
| NES / FDS | NES 的已验证 Nestopia 构建使用自带修正版；其他核心按本地安装情况选择 | 部分游戏已完成双机画面与输入同步、重复开局、交换角色和网络恢复；修正版通过炸弹人2状态恢复与同步校验测试 |
| SFC / SNES | 保留原已支持的本地核心；原核心不满足准入时查找已安装候选 | 有原生联机准入、渲染、负荷采样和恢复记录；复杂双人战斗仍需实测 |
| MD / SMS / Sega CD / 32X | 保留可用核心，必要时选择 Genesis Plus GX / PicoDrive 候选 | 部分平台有准入、渲染和恢复记录；需要逐款确认多人模式与性能 |
| PC Engine | 已安装、满足准入的固定候选 | 已提供核心选择；游戏联机仍需验证 |
| Neo Geo / CPS / 街机 | 已安装 FBNeo / MAME 等满足准入的候选；指定快打旋风内容与 64 位 MAME 0.275／FBNeo 构建匹配时，初始联机选择 FBNeo | ROM 必须匹配核心版本；《合金弹头 2》已报告联机卡顿 |
| PS1 | 保留可用核心，必要时选择 32 位 PCSX-ReARMed 候选 | 已提供核心选择；游戏联机与性能仍需验证 |
| GB / GBC | 已安装 TGB Dual | 同一卡带双屏连接线模式，房主控制左屏、加入者控制右屏；游戏内通信仍需验证 |
| GBA | 已安装 gpSP，按识别的游戏代码配置 Netpacket | 为已识别游戏配置无线适配器或连接线协议；游戏内通信待实测 |

联机按游戏平台选择已安装的核心。GB/GBC 使用 TGB Dual 的双屏连接线模式，GBA 按游戏代码选择 gpSP 的通信协议。创建和加入房间前会核对本地模拟器、核心与游戏内容。

快打旋风性能规则同时检查已验证内容、源核心和目标核心的完整 SHA-256 与 64 位 ABI；未匹配规则或缺少目标时保留原选核逻辑。更换后重新核对实际内容，加入匹配与启动重验证使用已选核心。

## 两端匹配

两台分别准备相同游戏和匹配的核心。加入房间时，工具核对模拟器位数、核心版本和游戏内容。ZIP 按对应核心的归档加载方式处理；街机 ROM 集需要匹配核心版本。

## 存档与玩家人数

每个房间有两位玩家：一位房主、一位加入者。每次联机从独立的空存档开始，临时存档随会话结束清理。

## 游戏表现

已验证的 64 位 RetroArch 构建使用低开销整状态压缩，保留周期同步校验。SNES 的启动阶段实测中，两次平均压缩耗时由约 540 ms 降至 117 ms，压缩数据由约 32 KiB 增至 36 KiB。游戏持续帧率取决于核心、场景、设备温度和链路状况。

《合金弹头 2》有单机顺畅、联机卡顿的实测反馈。报告卡顿时，请附上同一台掌机、同一核心、同一场景的单机与联机对照。
