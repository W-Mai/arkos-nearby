# 设备与游戏兼容性

## 设备配置

适用配置为 R36S、ArkOS4Clone 08262026、Linux ARM64 4.4.189、RTL8188EU 无线芯片和 640×480 屏幕。支持的无线 USB ID 为 `0bda:8179` 和 `0bda:0179`，内核文件 SHA-256 为 `73a123c06c67c002605bef637ef458aa43448a501c48ce27756f16e846d57f7a`。

运行时使用掌机已有的 RetroArch、核心、EmulationStation、gptokeyb、systemd、NetworkManager 和基础网络工具。执行 `doctor` 可查看掌机配置与依赖检测结果。

## 平台范围

| 平台 | 核心选择 | 已验证范围与限制 |
| --- | --- | --- |
| NES / FDS | 优先使用工具优化版 Nestopia，随后检查设备原有 Nestopia、FCEUmm | 部分游戏已完成双机画面与输入同步、重复开局、交换角色和网络恢复；修正版通过炸弹人2状态恢复与同步校验测试 |
| SFC / SNES | 优先使用设备原有 Snes9x，再检查其他已安装 SNES 核心 | 《超级炸弹人5》已验证从游戏入口建房、FN+X 或 SELECT 加入后的开局、菜单与地图推进、退出恢复网络 |
| MD / SMS / Sega CD / 32X | 按平台选择 Genesis Plus GX / PicoDrive | 部分平台有准入、渲染和恢复记录；需要逐款确认多人模式与性能 |
| PC Engine | 已安装并满足准入的 PC Engine 核心 | 已提供核心选择；游戏联机仍需验证 |
| Neo Geo / CPS / 街机 | 单机与建房均检查已安装的 ARM64 FBNeo、FBNeo Plus 与 MAME，采用通过游戏载入与状态回读的核心 | 两端使用相同核心与内容；MAME 街机以 ROM 模式启动，支持子目录归档 |
| PS1 | 优先选择已安装的 32 位 PCSX-ReARMed | 已提供核心选择；游戏联机与性能仍需验证 |
| GB / GBC | 已安装 TGB Dual | 同一卡带双屏连接线模式，房主控制左屏、加入者控制右屏；游戏内通信仍需验证 |
| GBA | 已安装 gpSP，通信协议设为自动 | 核心根据卡带识别无线适配器或连接线协议；在游戏内进入通信模式，实际支持范围随核心版本和游戏而定 |

联机按游戏平台选择已安装的核心。GB/GBC 使用 TGB Dual 的双屏连接线模式，GBA 使用 gpSP 的自动通信协议识别。创建房间时核对本地游戏；加入者连接房间后读取所需核心，核对本机内容与模拟器，再通知房主就绪。

单机与联机的各入口共用同一套选核规则，核心来源显示为「工具优化」或「设备原有」。街机按 FBNeo、FBNeo Plus、MAME 的固定顺序检查实际 ROM、BIOS 与状态保存和恢复，通过后采用；加入者使用房主确定的相同核心。单机继续使用系统存档和配置，联机会话保持独立存档并在退出时恢复网络。

## 仅组网

仅组网为支持局域网联机的游戏建立设备间连接。组网完成后返回系统，启动游戏并使用其局域网房间功能；游戏内容和通信由游戏本身处理。

两台 R36S 使用 FC-16《星跃竞速》完成了房间发现、双人开局和房主操作同步测试。交换组网房主、返回系统后保持连接、重新打开连接界面，以及断开后恢复 Wi-Fi 均已实机验证。

## 两端匹配

两台分别准备相同游戏和匹配的核心。加入房间时，工具核对模拟器位数、核心版本和游戏内容。ZIP 按对应核心的归档加载方式处理；街机 ROM 集需要匹配核心版本。

## 存档与玩家人数

每个房间有两位玩家：一位房主、一位加入者。每次联机从独立的空存档开始，临时存档随会话结束清理。

## 游戏表现

已验证的 64 位 RetroArch 构建使用低开销整状态压缩，保留周期同步校验。SNES 的启动阶段实测中，两次平均压缩耗时由约 540 ms 降至 117 ms，压缩数据由约 32 KiB 增至 36 KiB。游戏持续帧率取决于核心、场景、设备温度和链路状况。

《合金弹头 2》有单机顺畅、联机卡顿的实测反馈。报告卡顿时，请附上同一台掌机、同一核心、同一场景的单机与联机对照。
